# 과제 14: 힙 정렬, 퀵 정렬 및 병합 정렬의 성능 비교

## 1. 실행 방법
```bash
g++ -O2 -std=c++17 main.cpp -o main && ./main
```
- 난수 시드 고정(2024), 값 범위 `[0, 100000)`, 중복 허용. 모든 알고리즘은 같은 원본의 **복사본**을 정렬.
- 매 실행 후 `std::sort` 결과와 비교해 정렬 정확성 검증 (모든 결과 `OK`).
- 시간은 복사·생성·출력을 제외한 정렬 구간만 `chrono::steady_clock`으로 측정, 노이즈를 줄이기 위해 **10회 평균**(비교 횟수·메모리는 매번 동일).

## 2. 구현 요약
- **힙 정렬**: 입력 배열 자체를 최대 힙으로 사용(제자리). 반복문 기반 `siftDown`. 비교 = (두 자식 비교) + (부모와 큰 자식 비교), 힙 구성과 복구 모두 집계.
- **병합 정렬**: 하향식(top-down), 임시 배열 1개를 한 번만 할당.
- **퀵 정렬**: Lomuto 분할. 피벗 3종: 첫 원소 / 무작위 / 세 원소 중앙값(first, middle, last). 중앙값 선택의 비교(최대 3회)도 집계. 반복문 인덱스 검사는 제외.

## 3. 메모리 측정(계산) 방법 및 기준
원본 배열은 공통 비용이므로 제외하고 **추가 메모리의 최댓값**을 직접 계산했다.

| 알고리즘 | 계산식 |
|---|---|
| 힙 정렬 | 보조 변수 int 6개(`n, i, end, c, size, tmp`) = **24B**, 재귀 없음 → n과 무관 |
| 병합 정렬 | 임시 배열 `n × 4B` + 최대 재귀 깊이 × 48B |
| 퀵 정렬 | 최대 재귀 깊이 × 48B (보조 배열 없음) |

- 최대 재귀 깊이는 실행 중 직접 추적한 값을 사용.
- **48B**는 재귀 호출 1회의 스택 프레임 추정값(인자 포인터 8B + int 인자/지역변수 + 복귀 주소 8B + 저장된 프레임 포인터 8B 등)으로, 컴파일러·플랫폼에 따라 다를 수 있는 **근사치**이다.

## 5. 분석

### 5.1 데이터 크기 증가에 따른 비교 횟수
세 알고리즘 모두 n이 2배가 될 때 비교 횟수가 약 2.1~2.3배 증가해 **O(n log n)** 경향을 보인다(예: 힙 83,428 → 182,937 → 397,739). 다만 상수 계수가 다르다. 병합 정렬이 n=20,000에서 260,968회로 가장 적고 약 `n log₂n`(≈286,000)에 가깝다. 이는 두 정렬된 부분을 병합할 때 한 번 비교로 원소 하나를 확정하기 때문이다. 퀵 정렬은 324,155~352,432회로 병합보다 25~35% 많다. 평균 비교 횟수가 약 1.39 n log₂n이고, 분할이 항상 반반으로 나뉘지 않기 때문이다. 힙 정렬은 510,709회로 병합의 약 **2배**로 가장 많다. `siftDown`이 한 단계마다 "두 자식 비교 + 부모와 비교"로 **2번** 비교하고, 정렬 단계에서 맨 끝 원소를 루트에 놓고 내려보내므로 대부분 바닥까지 내려가 이점이 거의 없기 때문이다(약 2n log₂n).

### 5.2 실행시간 차이
시간은 비교 횟수 순서와 **다르다**. 비교가 가장 적은 병합 정렬(n=20,000에서 1.363ms)이 퀵 정렬(First 1.127ms, Median3 1.162ms)보다 느리다. 병합 정렬은 임시 배열로 쓰고 다시 원본으로 복사하는 데이터 이동이 많고, 퀵 정렬은 연속된 배열을 앞에서부터 훑으며 제자리에서 교환하므로 캐시 지역성이 좋다. 힙 정렬(1.363ms)은 비교가 가장 많은 데다 `2i+1`, `2i+2`로 멀리 떨어진 위치를 접근해 캐시 효율이 낮아, 비교 횟수 대비 느린 편이다. 이처럼 **비교 횟수만으로 속도를 판단할 수 없고 메모리 접근 패턴과 이동 횟수도 영향을 준다**. 단, n이 작을 때는 차이가 작고 측정 오차의 영향이 있다.

### 5.3 메모리 사용량
힙 정렬은 입력 배열 자체를 힙으로 쓰고 재귀가 없어 **24B로 n과 무관한 O(1)**이다. 병합 정렬은 임시 배열 때문에 n에 비례해 증가해 n=20,000에서 80,768B로 가장 크다(임시 배열 80,000B + 스택 768B). 퀵 정렬은 임시 배열이 없고 재귀 스택만 쓰며 1,248~1,680B로 작다. 이는 재귀 깊이가 평균적으로 O(log n)이기 때문이다(단, 최악의 경우 O(n)).

### 5.4 퀵 정렬의 피벗 선택 방법
무작위 데이터에서는 세 방법의 차이가 크지 않다. **Median3**가 모든 n에서 비교 횟수가 가장 적거나 거의 같았고(n=20,000에서 324,155회) 스택 깊이도 가장 얕아 메모리가 가장 작았다(1,248B). 세 값의 중앙값은 극단적으로 치우친 분할을 피하게 해 주기 때문이다. **First**는 입력이 무작위일 때만 괜찮고, 이미 정렬된 데이터에서는 분할이 한쪽으로 몰려 O(n²)이 될 수 있다. **Random**은 입력 순서에 상관없이 평균 성능을 기대할 수 있지만, 난수 호출 비용이 있고 운에 따라 편차가 있다(n=4,000에서 64,671회로 First, Median3보다 많았음). 이번 실험은 무작위 입력이라 First도 나쁘지 않게 나왔으며, 이는 First의 장점이라기보다 입력 조건 덕분이다.

### 5.5 시간·공간 복잡도 비교

| 알고리즘 | 최선 | 평균 | 최악 | 공간 | 특징 |
|---|---|---|---|---|---|
| 힙 정렬 | O(n log n) | O(n log n) | O(n log n) | O(1) | 제자리, 안정 정렬 아님, 비교 많음 |
| 병합 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 안정 정렬, 비교 적음, 추가 메모리 필요 |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | O(log n) (최악 O(n)) | 빠른 실측, 피벗에 민감 |

실험 결과와 이론은 일치한다. 힙 정렬은 메모리가 일정(24B)하고, 병합 정렬은 n에 비례해 증가(O(n))하며, 퀵 정렬은 작은 스택(O(log n) 수준)만 사용했다.

### 5.6 결론
- **최악의 경우까지 보장된 시간 + 메모리 절약**: 힙 정렬 (단, 느리고 비교 많음)
- **비교 횟수 최소 + 안정 정렬**: 병합 정렬 (단, O(n) 추가 메모리)
- **평균적으로 가장 빠른 실행시간**: 퀵 정렬, 피벗은 Median3가 안정적
